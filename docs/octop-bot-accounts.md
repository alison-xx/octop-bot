# Octop Bot 两套账号：本地 Octop 账号 与 灵策智算账号（设计稿，2026-11-25；§6 已由用户确认）

用户 11-25 定了方向，选的是方案 C「本机运行 + 云端同步」。这份文档替换 `octop-bot-cloud-plan.md` §12.4 里桌面端的部分：那一节写的是「去掉 Octop 密码、本机用法免登录」和 11-24 的方案 B「登录灵策就把数据搬到 bot.lynxce.cn，桌面变成云端的客户端」。网页、手机和自建服务器的部分不变。

## 0. 第一原则

> 灵策智算账号负责云端协同；本地 Octop 账号负责隐私隔离。

| | 本地 Octop 账号 | 灵策智算账号 |
|---|---|---|
| 作用 | 隐私隔离：数据只在这台电脑上，不上云，也不经过灵策 | 云端协同：多端同步，手机和网页上可以接着聊，团队和群组协作，用灵策的模型和积分 |
| 怎么来 | 第一次打开桌面客户端时，像上游 Octop 一样设置管理员账号、密码和模型 | 灵策手机号或邮箱验证码、密码、WorkBuddy 登录，没有账号就自动注册 |
| Bot 在哪跑 | 本机 Octop | 在本机发的消息由本机 Octop 跑；在手机或网页发的消息由云端 Octop（bot.lynxce.cn）跑 |
| 模型和计费 | 自己配：厂商 API Key（腾讯云、百炼、方舟……）或本地模型（Ollama、LM Studio），不走灵策 | 灵策模型扣灵策积分；也可以用「我的 API Key」，由厂商收费 |
| Bot 的电脑 | 这台电脑（授权给 Bot 的本机应用） | 本机发的消息用这台电脑；云端发的消息用云电脑（CVM / AGS），按分钟扣积分 |

**边界**：灵策账号是挂在本地账号上的一个「可选连接」，不是另一套数据。本地账号永远是这台电脑上数据的主人；登录灵策后，只有用户标成「协同」的 Bot 才会上云。

## 1. 两套账号的关系

### 1.1 本地 Octop 账号
- 首次启动（全新安装）恢复上游 Octop 的做法，也就是 §12.4 之前的样子：
  1. 设置管理员用户名和密码（密码至少 8 位，本机存哈希）。
  2. 配置模型，三选一：「我的 API Key」「本地模型」「登录灵策智算」。选了灵策，就进入 §1.2 的绑定流程。
- 设好以后，日常打开**不用再输密码**：沿用现在的设备凭据（`/api/auth/device/*`，壳把凭据存在钥匙串里）自动登录。下面几种情况才要输密码：设备凭据失效；在「设置 → 账号与积分」里改安全设置；从局域网或别的设备访问这台电脑上的 Octop（上游的多用户和远程访问场景）。
- 一台电脑可以有多个本地账号（上游本来就是多用户）。每个本地账号各自绑定自己的灵策账号，数据互相隔离。
- **已经装过的用户**：现在本机用法用的是 `local` 账号加设备凭据，没有密码。升级后第一次打开时提示「为这台电脑设置一个密码」，这一步可以跳过，但会一直提醒。数据不用迁移。

### 1.2 灵策账号挂在本地账号上
- 每个本地账号**同一时间最多绑一个**灵策账号。绑定关系保存在本机：沿用现在 `secret_repo` 里加密保存的会话 `lynxce.cloud.user.{uid}`（`infra/auth/lynxce_cloud.py`），和 `settings_repo` 里的模型 Key 归属 `octop_bot:lynxce:key_owner:{uid}`（`infra/agents/providers/lynxce.py`）。
- 绑定以后：
  - 模型默认用灵策（1.0.5 已做好：登录就签一把个人 Key，`CloudAccountModel`，扣灵策积分）；
  - 积分、充值和用量页显示这个灵策账号的数据；
  - 「协同」Bot 开始同步（§2）。
- **退出灵策**：协同 Bot 留在本机，变成「已断开」（还能在本机用，只是不再同步）；云端那份保持不动。重新登录同一个灵策账号就接着同步。
- **换另一个灵策账号**：和退出一样，先断开旧账号。旧账号的协同 Bot 在本机还是「已断开」，不会同步到新账号；新账号的协同 Bot 从云端拉下来。同一个 Bot 不会同时属于两个灵策账号。
- **只登录灵策、不设本地密码**是允许的，本地账号照样在后台建好，只是没有密码。这适合只想用灵策的人，和现在 1.0.5「选灵策智算」的体验一样。

### 1.3 一眼看出属于哪边
- Bot 头像右下角加小标：**🔒 本机**（不上云）、**☁ 协同**（同步到灵策云）、**⚠ 已断开**（协同 Bot 现在没有同步）。会话标题旁边、群聊成员列表里也显示同样的标记。
- Bot 资料页有一个「同步到灵策云」开关，旁边一行说明：「打开后，这个 Bot 的设置、对话和它发给你的文件会保存到灵策云，手机和网页可以接着聊；它在这台电脑上读过的文件、操作过的应用不会上传。」
- 手机和网页上只看得到协同 Bot。本机 Bot 在那里根本不存在，不是「看得到但不能聊」。
- 侧边栏可以按「本机 / 协同」筛选，账户菜单显示「灵策已连接 · 同步中 / 已暂停」。

## 2. 方案 C：同步怎么做

### 2.1 同步什么（只针对协同 Bot）

| 数据 | 同步 | 说明 |
|---|---|---|
| Bot 设置（名字、形象、人设/系统提示、所选模型、技能清单、连接器开关） | ✓ 双向 | 连接器的凭据**不**同步；云端没有的本机连接器在云端显示为「仅本机」 |
| 会话和消息（用户消息、Bot 最终回复、提问卡、附件卡） | ✓ 双向 | 工具调用的**原始输出不上云**，只同步一句摘要，例如「读取了 report.xlsx」。云端的模型上下文用回复和摘要 |
| Bot 发出的文件、用户上传的附件 | ✓ 双向 | 只同步消息里引用到的文件，走对象存储，按现在云端租户的 `octop-bot/` 前缀 |
| Bot 的整个工作区 | ✗（第三期可选） | 工作区里可能有从本机复制进来的文件 |
| 记忆（长期记忆） | ✓ 双向（第三期） | 由用户单独确认：「记忆也同步」默认打开，可以关掉。关掉后两边各记各的 |
| 群组（成员、时间线、Goal、阶段） | ✓（成员全是协同 Bot 的群才同步） | 群里只要有一个本机 Bot，整个群就留在本机，群头显示 🔒 |
| 团队笔记、侧边栏分组 | ✓ | |
| 引导状态 `octop_bot:onboarding:<uid>` | ✓ 跟着灵策账号走 | 登录了灵策：所有设备只引导一次（以云端那份为准）。只用本地账号：本机单独引导一次 |
| 本机账号密码、设备凭据、厂商 API Key、本机连接器凭据、本机电脑授权 | ✗ 永不上云 | |
| 本机 Bot 的一切 | ✗ 永不上云 | |

### 2.2 方向和冲突
- **云端是中心**：灵策账号在 bot.lynxce.cn 上就是一个租户，和现在一样。每台桌面是这个租户的一份副本：本机 Octop 里的同步程序带着灵策会话，从云端拉变更、把本机变更推上去。
- **变更流**：云端每个租户维护一个递增序号（新增一张 `sync_changes` 表，SQLite 和 PG 各一份迁移）。客户端只要报上次的游标，就拿到之后的增量；推送时每条带 `origin_id`，重复推送不会产生重复数据（沿用 8771b684 搬入接口「每条带来源」的做法）。
- **冲突**：
  - 消息只追加，按 id 合并，不会冲突。
  - **同一个会话同一时刻只有一处在跑回合**：开始一个回合前，先向云端申请这个会话的「运行租约」（大约 2 分钟，跑的过程中不断续期）。另一端看到「正在别处回复」，可以等它跑完，也可以停掉它。离线的桌面拿不到租约时照样跑，联网后把这一回合追加在后面，并且标注「离线回复」。
  - Bot 设置：每个字段后写入的覆盖先写入的（字段级 LWW，带版本号）。覆盖时在 Bot 资料页的「最近修改」里留一条记录。
  - 记忆：按条目 id 合并，删除用墓碑（tombstone）同步。

### 2.3 在手机或网页上「接着聊」时 Bot 在哪跑
- **云端跑**：手机和网页发的消息由云端 Octop 跑这一回合，用灵策模型（或这个账号保存的厂商 Key），需要电脑时用云电脑。**桌面离线也能聊**，这正是方案 C 的价值。
- 云端回合碰不到本机：本机文件、本机应用、本机连接器都用不了。Bot 需要这些时，给出一张「交给电脑」卡片（第三期），任务进入队列，桌面上线后由本机接着做，结果同步回来。第二期先简化成 Bot 直接告诉用户「这件事要在电脑上做」。
- 在桌面上发的消息永远由本机跑（隐私优先），默认用这台电脑；用户主动要求时才用云电脑（见 2.4）。

### 2.4 云电脑归属
- 云电脑属于灵策账号（云端租户），每个协同 Bot 一台。这和现在的租户模型一样，计费不变。
- 本机 Bot（🔒）没有云电脑，只用这台电脑。
- 协同 Bot 在桌面上跑回合时，默认用这台电脑。要用自己的云电脑，需要 §12.4 计划里的「远程云电脑」接口（`/api/octop-bot/remote-computers/{key}`，还没实现），放在第三期。

### 2.5 和现有 bot.lynxce.cn 多租户云的关系
- 不动多租户：灵策账号在云端仍然是一个租户，网页和手机的用户继续直接用它。方案 C 只是让桌面成为这个租户的一份副本，外加同步接口：
  - `GET /api/octop-bot/sync/changes?after=`
  - `POST /api/octop-bot/sync/push`
  - `POST /api/octop-bot/sync/lease`
- 只用过网页或手机的老用户，装桌面并登录灵策后，他的 Bot 从云端拉下来，全部标为协同。

## 5. 风险
1. **隐私泄漏的口子**：协同 Bot 在本机读过的文件内容，可能以引用、摘要的形式出现在它的回复里，回复会上云。工具的原始输出虽然不同步，但模型自己写进回复的内容挡不住。缓解办法：打开同步开关时讲清楚；敏感的工作放在 🔒 Bot 上做。
2. **群组跨界**：混合群（本机 Bot 加协同 Bot）只能留在本机，用户可能以为手机上能看到。缓解：群头显示 🔒，并说明原因。
3. **双端同时跑**：租约过期、桌面离线回复，都可能让一个会话出现两条并行的回复。缓解：标注「离线回复」，不合并、不覆盖。
4. **数据库迁移**：新增同步表和每条记录的同步状态，要走编号迁移（SQLite + PG）。上游同步时要注意编号冲突，#3130 已经撞过一次。
5. **上游分叉**：本地账号恢复上游流程是好事，但 Octop Bot 的首启页要和上游的 setup 向导对齐，不能各写一套。
6. **计费**：桌面回合和云端回合都扣同一个灵策账号的积分，用量页要能按「本机 / 云端」区分，否则用户看不懂为什么关着电脑还在扣积分。
7. **灵策账号注销**：云端数据会按灵策的冷静期删除，本机副本保留并标为「已断开」。这一点要写进注销提示。

## 6. 已定（2026-11-25 用户确认：9 条全按建议）
1. **共存方式：按 Bot 分（有的本机、有的协同），还是整台电脑二选一？** 已定：**按 Bot 分**。这最符合「本地隐私隔离」：私密的事交给 🔒 Bot，需要手机接着聊的交给 ☁ Bot。
2. **登录灵策以后，新建的 Bot 默认是什么？** 已定：**登录前已有的 Bot 一律保持 🔒，不自动上云；登录后新建的 Bot 默认 ☁，创建时可以改**。手机和网页上建的 Bot 本来就是 ☁。
3. **工具调用的原始输出上不上云？** 已定：**不上**，只同步摘要。代价是云端接着聊时，看不到桌面回合里读到的原文。
4. **记忆同步：默认打开，还是默认关闭？** 已定：**打开**（Bot 换个端就失忆，体验很怪），但在同步开关旁边单独列一行，可以关掉。
5. **手机或网页接着聊时，桌面离线由谁跑？** 已定：**云端代跑**（方案 C 的价值就在这里），碰不到本机的事情说明一下，或者放进第三期的「交给电脑」。另一个选择是「只读，等电脑上线」，更保守，但手机基本用不起来。
6. **本地账号要不要每次输密码？** 已定：**只在首次设置时输**，之后靠设备凭据自动登录；改安全设置和远程访问时才要密码。
7. **只用灵策、不设本地密码，允许吗？** 已定：**允许**（本地账号在后台照样建好），但会持续提醒「为这台电脑设置密码」。
8. **新用户引导：跟着灵策账号只引导一次，还是每台设备各引导一次？** 已定：**登录了灵策就跟着账号走（只一次）**，没登录的本机引导一次。
9. **退出或切换灵策账号时，协同 Bot 怎么办？** 已定：**留在本机、标「已断开」**，不删除、不迁到新账号。

# Octop Bot SaaS：灵策账号登录，模型自选

> 状态：设计稿（2026-11-24），尚未实现。承接 `docs/octop-bot-cloud-plan.md`（云 Octop、AGS 云电脑、积分）和 `feature/bot-p4-two-modes` 的「本机 / 灵策智算」两种用法。

## 0. 结论先行

1. **账号只有一个：灵策智算账号。** 四端用同一个灵策账号登录，第一次登录即注册。登录后数据在云 Octop（`bot.lynxce.cn`），桌面、网页、iOS、Android 看到同一个团队，关机后 Bot 和定时任务照常在云上跑。
2. **模型来源和账号解耦，用户自己选。** 每个用户可以有三类模型来源，每个 Bot 单独挑模型：
   - **灵策模型**：默认，零配置，按积分扣费。
   - **三方厂商 API（自带 Key）**：OpenAI、Anthropic、Gemini、DeepSeek、通义千问、Kimi、智谱、豆包、硅基流动、OpenRouter，以及任意 OpenAI 兼容地址。模型费用由厂商直接向用户收。
   - **本地模型**：用户电脑上的 Ollama、LM Studio、vLLM 等。云端访问不到用户的 `localhost`，所以由已登录的桌面客户端做「模型中继」，把云端 Bot 的请求转给本机模型。
3. **执行面和模型无关。** 不管用哪类模型，Bot 的云电脑（AGS）、文件（COS）都照旧，按积分扣费。
4. **不登录也能直接用（已定）。** 桌面开始页给两条路：「登录灵策智算」和「不登录，自己配置模型」。后者进入本机模式，用户配置本地模型或三方 API Key 后直接进 Octop Bot，数据和 Key 都留在这台电脑。之后随时可以登录灵策智算，升级为云端用法。设计稿见 Artifact「Octop Bot 登录与模型设置」。

## 1. 为什么要改

现状（`dev/latest-all`，2026-11-24）：

| 现在 | 问题 |
|---|---|
| 云端租户只能用灵策模型：`account_selection()` 在云模式下一律返回租户自己的灵策 Key（`src/octop/infra/agents/providers/lynxce.py:261`） | 已有 API Key 或本地模型的用户进不来 |
| `providers` 表整台服务器共用，`name` 全局唯一（`001_initial.sql:52`），只有管理员能配 | 多租户下不能让用户各配各的 |
| 桌面端登录灵策后，Bot 仍跑在本机 Octop，云电脑要靠 p4 设计的 `remote-computers` 绕一圈 | 两套数据位置，四端不一致；用户以为登录了就有云电脑，实际没有 |
| `bot.lynxce.cn` 当前 502 | SaaS 主路径还没上线 |

## 2. 产品形态

```
                 灵策账号（唯一身份、钱包、充值）
                              │
         ┌────────────────────▼─────────────────────┐
         │   云 Octop（bot.lynxce.cn，多租户）        │
         │   Bot / 群 / 记忆 / Cron / 用量             │
         │                                           │
         │   模型路由（每个 Bot 一个模型引用）          │
         │   ├─ lynxce:<model>   → 灵策网关，扣积分     │
         │   ├─ byok:<id>:<model> → 厂商 API，用户 Key │
         │   └─ relay:<dev>:<model> ─┐                 │
         └───────────┬───────────────┼─────────────────┘
                     │               │ WSS（桌面主动连上来）
           AGS 云电脑 + COS          ▼
                         用户电脑上的桌面客户端
                         └─ localhost:11434 Ollama / :1234 LM Studio …
```

| | SaaS（主路径） | 本机（桌面可选） |
|---|---|---|
| 登录 | 灵策账号，必须 | 不用 |
| 数据 | 云 Octop | 本机 `~/.octop-bot` |
| 模型 | 灵策模型 / 自带 Key / 本地模型（经中继） | 本机配置的任意模型，也可连灵策账号模型 |
| Bot 的电脑 | 云电脑（AGS），积分 | 这台电脑上授权的应用 |
| 多端同步、关机后继续 | 有 | 无 |

## 3. 模型来源

### 3.1 数据模型

新增资源表 `user_model_providers`（遵循 AGENTS.md 资源表约定，SQLite 与 PostgreSQL 各一份迁移，并入当前未发布的迁移号）：

| 列 | 说明 |
|---|---|
| `id` | 整数主键 |
| `provider_id` | 对外字符串 id（ULID） |
| `user_id` | 所属用户（整数，`users` 表约定） |
| `kind` | `openai_compatible` / `anthropic` / `gemini` / `relay` |
| `preset` | 厂商预设名（`deepseek`、`dashscope`、`moonshot` …），自定义为空 |
| `base_url` | 厂商地址；`relay` 时为空 |
| `api_key_enc` | 加密后的 Key；`relay` 时为空 |
| `device_id` | `relay` 专用：提供模型的桌面设备 |
| `models_json` | 可用模型及能力（工具调用、视觉、上下文长度） |
| `enabled`、`created_at`、`updated_at` | |

- 每个 Bot 的模型存成一个引用字符串：`lynxce:<model>`、`byok:<provider_id>:<model>`、`relay:<provider_id>:<model>`。用户另有一个默认引用，新 Bot 和 Chief 用它。
- 实例级 `providers` 表保留给自建服务器和管理员，云模式下租户看不到也用不了。
- 删除来源时，引用它的 Bot 退回用户默认模型，并在 Bot 资料页提示。

### 3.2 自带 Key（BYOK）

- **加密存储**：复用 `infra/connectors` 的凭证加密；读接口永远不返回明文，只显示后四位。日志、错误信息、轨迹里不出现 Key。
- **测试连接**：保存前调用一次 `/models` 和一次带工具调用的最小对话。不支持工具调用的模型可以选，但标注「不能使用工具，只能聊天」，因为 Bot 的大部分能力依赖工具调用。
- **出站安全（云端必需）**：`base_url` 只允许公网 HTTPS；解析 DNS 后拒绝私网、回环、链路本地和云元数据地址（`169.254.169.254` 等），连接时固定已解析的 IP，防止 DNS 重绑定。超时、单租户并发和速率都有上限。
- **错误码**：Key 无效 `BOT_BYOK_AUTH_FAILED`，厂商额度用完 `BOT_BYOK_QUOTA`，厂商不可达 `BOT_BYOK_UNREACHABLE`。客户端按错误码显示卡片（「去改 Key」「换模型继续」），和积分不足卡片同一套样式。
- **做图、做视频**：先只走灵策（`generate_image` / `generate_video`），以后再开放自带 Key。

### 3.3 本地模型（桌面中继）

云 Octop 访问不到用户电脑，所以反过来，由桌面客户端连上云端：

1. 桌面登录灵策后，设置里有「本地模型」开关。打开后自动探测 `localhost:11434`（Ollama）和 `localhost:1234`（LM Studio），也可以手填本机或局域网地址。用户勾选要共享给云端 Bot 的模型。
2. 桌面向云 Octop 建立一条 WSS（`/api/octop-bot/relay`），带上设备 id 和勾选的模型清单。云端为它建一条 `kind=relay` 的来源。
3. Bot 用到中继模型时，云 Octop 把 OpenAI 兼容请求通过这条 WSS 发给桌面，桌面只转发给用户勾选过的本机地址，再把流式结果传回。云端不能借这条通道访问桌面上的其他地址。
4. **电脑离线时**：每个 Bot 可设「本地模型不可用时」改用默认模型或直接报错，默认改用默认模型。定时任务同样处理。报错码 `BOT_RELAY_OFFLINE`。
5. **要对用户说清楚**：用了本地模型，对话内容仍然存在云 Octop，经过云端转发。想让数据完全不出电脑，请用本机模式。界面上这句话放在开关旁边。
6. 手机不能提供本地模型，但可以使用桌面在线时共享出来的模型。

### 3.4 模型选择器

- 设置 →「模型」分三组：「灵策模型」「我的 API Key」「本地模型（来自 <设备名>）」。每组下面列可用模型，右侧写清谁收费：「积分」「你的 Key」「你的电脑」。
- Bot 资料页的模型选择器用同样的分组，并显示该模型是否支持工具和图片。
- 添加 Key：选厂商 → 粘贴 Key → 测试 → 勾选模型 → 保存。自定义地址多一个「接口地址」输入框。

## 4. 计费与配额

- **灵策模型**：照旧按 token 扣积分（`BOT_CLOUD_CREDITS_REQUIRED` 等错误码不变）。
- **自带 Key、本地模型**：模型费用不经过我们。
- **云电脑、存储**：不论哪类模型都按积分扣费。
- **控制面成本**：只用自带 Key 的用户也占用云 Octop 的计算、存储和定时任务。用套餐配额兜底：Bot 数、群数、定时任务数、并发回合数。是否另收平台费见 Q3。
- **用量页**：「按模型」再分来源，自带 Key 和本地模型只显示 token，不显示积分。

## 5. 各端改造

| 端 | 改动 |
|---|---|
| 云 Octop | `user_model_providers` 表与仓储；模型路由支持三种引用；BYOK 测试、加密、出站防护；中继 WSS 与 `relay` 适配器；错误码与 i18n；用量按来源 |
| 桌面 | 登录灵策后连云端（取代 p4 里「本机 Octop + 灵策账号 + remote-computers」的组合）；本地模型探测、勾选、中继连接，托盘显示中继状态；本机模式保留 |
| 网页 / iOS / Android | 设置 → 模型三组；添加 Key 流程；Bot 模型选择器分组；新错误卡片 |
| 灵策 | 无新接口；继续提供登录、钱包、充值、模型网关 |
| 上游 octop-harness | 不需要改：模型客户端仍按 OpenAI 兼容或 Anthropic 协议创建，中继在 Octop 这层实现 |

## 6. 分期

1. **S1 SaaS 主路径上线**：部署 `bot.lynxce.cn`；桌面「灵策智算」直接连云端，四端一致；云电脑在桌面直接可用。基于 p4 的登录改造。
2. **S2 自带 Key**：表、加密、出站防护、预设厂商、测试连接、四端模型设置、Bot 选择器、错误卡片。
3. **S3 本地模型中继**：桌面探测与共享、WSS 中继、离线回退。
4. **S4 套餐与配额**：控制面配额、用量按来源、是否收平台费。
